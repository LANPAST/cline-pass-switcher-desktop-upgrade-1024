## 1. 一句话概览

这是一份 Cline Pass 上游观察 / 切换代理的桌面版。本次升级的核心，是发现并落地了
`providerOptions.gateway.has` 能力过滤：在规划器管道上，单独发 `only` 会被服务端忽略，
必须同时带上 `has`，`only` 才会真正生效。围绕这个结论补了验证、手动钉住、探测兜底、
人民币计价，并把应用改名为 `cline-pass-switcher-desktop-upgrade-1024`、版本升到 `2.4.0`。

## 2. 本次交付的功能

| 功能 | 说明 |
|---|---|
| 能力过滤 `has` | 每个模型可配 `perModel[model].has`；规划器管道下发 `providerOptions.gateway = { only/order/sort, has }` |
| 两组对照验证 | `POST /api/verify-pin`：A 组 `only=[目标]`+`has` 必须命中；B 组 `only=[不存在]`+`has` 必须被拒绝 |
| 手动钉住 | 探测不到渠道时，可在「订阅模型 → 渠道 → 手动添加渠道」里直接填 `deepseek` 等 slug |
| 探测兜底 | 枚举渠道时发现无效 `only` 被忽略/报 empty content，会带 `has` 重探，拿到候选渠道清单 |
| 人民币计价 | `deepseek-v4.1-flash-1017` 快照按官方 `deepseek-flash` 价目表计算 |
| 改名与版本 | `name/productName = cline-pass-switcher-desktop-upgrade-1024`，版本 `2.4.0`，构建产物名同步 |
| 数据兼容 | 应用显示名变了，但 `userData` 仍固定为 `%APPDATA%\Cline Pass Switcher`，升级不丢账号/密钥/历史 |
| 仓库安全 | 新增 `scripts/check-secrets.mjs`（`npm run check:secrets`），`.gitignore` 挡住本地运行数据 |
| 文档与截图 | README 顶部加入 2.4.0 更新亮点、实际效果图、LINUX DO 友情链接 |

## 4. 实测结论（重要，换 key / 换模型要重验）

### 4.1 已验证有效

`cline-pass/deepseek-v4.1-flash-1017`：

- 配置：`upstreams: ["deepseek"]`，`has: ["vision", "implicit-caching"]`
- `/api/verify-pin`：A 组实际 `deepseek`，B 组被拒绝，`enforced: true`
- `/v1/chat/completions` 非流式 / 流式都返回 `finalProvider: deepseek`
- 网关路由元数据里能看到：
  `Required capabilities [vision, implicit-caching]: all 1 attempts match`

`cline-pass/deepseek-v4-pro`：

- 配置：`upstreams: ["deepseek"]`，`has: ["implicit-caching"]`
- 实测同样 `enforced: true`，A 组命中 `deepseek`，B 组被拒绝
- 结论：纯文本 DeepSeek 模型单靠 `implicit-caching` 也能让 `only` 生效；不要加 `vision`，否则一个上游都匹配不到

### 4.2 已验证无效

`cline-pass/deepseek-v4.1-flash`（不带 `-1017`）：

- 手动钉 `deepseek`，无论 `has` 是 `vision` + `implicit-caching`、只有 `implicit-caching`、还是只有 `vision`
- 网关最终都返回 `openai-compatible-private`
- 这不是代码 bug；界面会如实显示「网关未采纳」。这个模型目前不要指望钉住

### 4.3 探测渠道

修复后，`deepseek-v4.1-flash-1017` 点「探测」可以枚举出 17 个渠道：
`alibaba, baseten, boundless, deepinfra, deepseek, fireworks, gmicloud, inference-net, morph, novita, parasail, pareto, particle, relace, runinfra, runware, togetherai`。

注意：这 17 个是模型可用渠道全集；带上 `has` 后真正能通过过滤的通常只有 `deepseek`，校验时其它渠道会显示「不可钉」，属于正常现象。

## 5. 机制与默认值（避免误改）

- `has` 是**排除性**过滤：不满足标签的渠道会全部消失。
- 默认值仅对「规划器 + 只钉 deepseek + 多模态（v4.1-flash / vision）」自动启用
  `vision` + `implicit-caching`；纯文本模型默认不自动启用，避免 `vision` 把上游全排除。
- 直连（OpenRouter）管道不发送 `has`，它本来就能透传 `provider.only`。
- 「校验全部渠道」会带上当前 `has`，所以结果反映的是过滤后的真实可钉性，不是「全部可用」。
- 两组验证的判定：A 组命中目标上游且 B 组被拒绝，才显示「已生效」；任何一边不成立都会如实提示。

## 8. 已知坑 / 待办

1. **`has` 是实测结论，不是文档承诺**：换 key、换模型、隔一段时间都可能变化，务必重新点两组验证。
2. **`deepseek-v4.1-flash` 钉不住**：目前没有找到有效的能力标签组合；`-1017` 可以。
3. **中文账号名的响应头是 `-`**：`headerSafe` 会把非 Latin-1 字符清掉，历史/统计里的账号名正常；只是 `X-Cline-Account` 头不可读。可选优化：百分号编码 + 前端解码。
4. **旧记录人民币为 0**：`-1017` 的人民币别名是本次新加的，历史记录需要点「重算人民币」补。
5. **截图标题栏是旧版 v2.3.3**：`docs/screenshots/pin-after.png` 是功能验证时截的，请求记录真实；介意的话可以重截或裁掉标题栏。
6. **安装包未签名**：Windows SmartScreen / macOS Gatekeeper 首次会拦。
7. **tag 落后 main 一个文档提交**：见上，发新版时再打 tag。

## 9. 换工作区 / 新会话怎么继续

当前 DSH 会话的工作区固定在：

```
G:\Git clone\cline-pass-switcher-desktop-2.3.3
```

新 clone 推荐：

```powershell
cd "G:\Git clone"
git clone https://github.com/LANPAST/cline-pass-switcher-desktop-upgrade-1024.git
cd cline-pass-switcher-desktop-upgrade-1024
npm install
```

然后在 DSH 里新开一个会话，工作区选新目录。新会话不会自动带旧对话上下文，
把这份 `docs/handover-2026-10-24.md` 指给它读即可。

旧会话记录在：

```
C:\Users\LANPA\.dsh\sessions\--G-Git~0020clone-cline-pass-switcher-desktop-2.3.3--\
C:\Users\LANPA\.dsh\storages\workspace.json
```

删除旧项目目录不会删这些会话文件；但为防工作区条目失效，归档会话并备份上述两个位置。
